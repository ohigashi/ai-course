# データの区分

Claude に読ませてよいかを、3つに分けて考えます。迷ったら「使わない」として、大東に相談します。

| 区分 | 例 | 扱い |
|---|---|---|
| 使ってよい | 公開されている情報、自分が書いた文章、社内の一般的な手順 | 自由に使う |
| 条件つき | 顧客名を伏せた文面、匿名にした数字 | 下の条件をすべて満たすときだけ、Claude に読ませてよい。リポジトリには置かない |
| 使わない | 個人情報、財務の実データ、契約の機微な情報、パスワードや API キー | Claude に読ませない。リポジトリにも置かない |

## 「条件つき」を使える条件

1. Claude Code の `/status` で、会社の Team または Enterprise のアカウントでログインしていると確かめた。個人のプラン(Free、Pro、Max)では使わない
2. 伏せたあとの内容から、どの会社や誰の話かが分からない。名前だけでなく、地域、日付、特徴のある金額からも分かることがあるので、必要なら丸めるか別の表現にする
3. 自分の会社の決まりや、顧客との契約で禁じられていない

3つのうち1つでも確かめられないときは、「使わない」と同じに扱います。

読ませた文面や数字は、Claude との作業の中で使うだけにします。`docs/`、`challenges/`、`team-share.json`、`/log` の記録には書きません。リポジトリに保存すると、運営者やチームの人にも見える場合があるためです。

## 本番の業務で財務の実データを使う例外

「使わない」のうち、領収書、請求書、取引一覧などの財務の実データは、会社の責任者と大東が個別に認めた業務に限って使えます。認められていない業務では使いません。次をすべて守ります。

1. 手動の実行も自動の実行も、会社の Team または Enterprise のアカウントで動かす
2. 対象の業務とデータを決めておく。別の業務やデータに広げるときは、改めて相談する
3. その業務の担当者だけが見られる場所で扱う(専用の非公開チャンネルなど)
4. 実データをリポジトリに置かない。`docs/`、`work/`、`/log` の記録、チームの一覧にも書かない。作るときと試すときはダミーを使う
5. 人に届く内容は、運用が安定するまで、人が確かめてから送る

マイナンバー、銀行の口座番号、パスワード、API キーは例外の対象にしません。取引先名や担当者名は、その業務に必要な範囲で扱い、結果の投稿には必要な情報だけを出します。

練習には、ダミーか機微な部分を除いたデータを使います。
