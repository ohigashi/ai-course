# /goal

受講者が自分の目標を書き、できるようになったことを確かめ、目標に合わせた次にやることを1つ決めます。受講者はエンジニアとは限りません。短く進めます。

目標の達成は判定しません。目標は本人が自分の位置を確かめるためのもので、結果は本人の感じ方で答えてもらいます。

## 手順

1. 材料を読む。`docs/goals.md`(無ければ初めて)、`CLAUDE.md`、`docs/01-tasks.md`、`works.json` があれば読む。`node scripts/history.mjs` を実行して、これまでの歩みを読む。`.local/log.md` があれば読む(内容を誰かに伝えたり、ファイルに書き写したりしない)
2. 目標を聞く。目標は1つから3つまで。前回の目標があれば見せ、そのままにするか変えるかを聞く。初めての人には次の例を見せる
   - 〇〇の業務の時間を30%減らす
   - 〇〇の資料を正確にしつつ、提案や報告までの時間を30%減らす
   - 自分で課題を見つけて、解決するアプリを3つ作る

   次の4点を伝える。数字は書かなくてよい。何度変えてもよい。目標の文は大東が支援のために読める。顧客名や個人の事情は書かない
3. 前回の目標があるときは、「楽になった仕事はありますか」「まだ時間がかかる仕事はどれですか」と聞く。答えは提案の材料にするだけで、ファイルに書かない
4. `node scripts/goal.mjs show` を実行して見せ、項目ごとに 1 から 10 を聞く。目安(1 やったことがない、4 AIや手順の助けがあればできる、7 一人でできる、10 人に教えられる)を添える。答えたくない項目や分からない項目は飛ばしてよいと伝える。答えを `node scripts/goal.mjs rate <項目>=<値> ...` で保存する(項目の名前は `course/abilities.json` の `id`)。値は自分のパソコンにだけ残り、誰にも見えないと伝える
5. もう一度 `node scripts/goal.mjs show` を実行し、前回より上がった項目を具体的な言葉で伝える。下がった項目は否定せず、理由も聞かない
6. 記録と答えから、「できるようになったこと」と「まだ試していないこと」を2〜3行で返す
7. 次にやることを1つ提案し、理由を1文添える。目標に関わる項目のうち、値の低いものや答えていないものを材料にする。本人の業務を題材にしたお題や課題を優先する。練習のデータはダミーにし、顧客データ、財務の実データ、個人情報は使わない。候補と保存の仕方は次のとおり。進むかどうか、どれを選ぶかは本人が決める
   - 今の取り組みを動かす: フェーズを動かすなら、了承を得て `node scripts/work.mjs move <slug> <N>`。フェーズ3か4の取り組みなら、本人が決めた文を `node scripts/work.mjs next <slug> <文>` で保存する。フェーズ1か2の取り組みは判定から次にやることが決まるので、`next` を上書きしない
   - 新しい取り組みを始める: 了承を得て `node scripts/work.mjs new <名前>` で作り、`node scripts/work.mjs next <slug> <文>` で保存する。取り組みの名前と次にやることは自動で大東に共有されるので、顧客名や個人の事情は書かないよう伝える
   - 仕組みのお題(`/mechanism`)、発展コース(`course/stepups/index.md`)、課題解決(`/challenge`): そのコマンドを案内する。新しく保存しない
8. `docs/goals.md` を次の形で書く。目標が変わらなければ日付だけ更新する

   ```
   # 目標

   - (目標1)
   - (目標2)

   更新: YYYY-MM-DD
   ```

   `git add docs/goals.md` のあと `git commit -m "目標の更新" -- docs/goals.md` を実行して push する
9. `node scripts/events.mjs add review` を実行する(今月はもう見直しを聞かない記録。歩みには出ない)

## 決まり

- できていることから書く。否定から入らない
- 次にやることは1つに絞る
- 自己評価の値を合計しない、平均しない。他の人と比べない。比べる相手は前回の自分だけにする
- 自己評価の値と目標を、進む条件や完了の判定に使わない
- 専門用語を避け、受講者の業務の言葉で書く
